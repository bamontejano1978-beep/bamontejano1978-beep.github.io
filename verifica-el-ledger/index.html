Verificación en tu dispositivo

Trae un ledger. Compruébalo tú, sin instalar nada y sin creernos.

Un ledger de auditoría no vale nada si solo lo puede verificar quien lo escribió. Exportamos el nuestro a un bundle y tu navegador recalcula la cadena SHA-256 completa: cada payload, cada hash, cada enlace con el anterior. Si alguien editó un byte después de escribirlo, lo ves aquí, en tu pantalla.

Verificar el ledger de demostración Cómo se produce un bundle

El ledger de demostración tiene cuatro eventos de verdad: un incidente detectado, una tarjeta de cambio generada, un sandbox aprobado por una persona y una revisión de release firmada. La firma Ed25519 la verifica el CLI, no esta página: aquí solo hay SHA-256 y tus ojos.

Pulsa un botón, o arrastra tu propio bundle.

    Antes de la página

    De dónde sale el bundle, en cuatro pasos.

    El bundle no se fabrica para la demostración: es la salida del mismo recorrido que usamos con un cliente. Un contrato, un candidato aprobado por una persona, una revisión independiente firmada y el ledger que lo registra todo. 

    # 1. Del contrato a la tarjeta de cambio: hipótesis, no cambios aplicados
python -m autopilot diagnose "examples/insurance_claims_v0.1.yaml" \
    "examples/insurance_claims_trajectory_fail_v0.1.yaml" --output-dir ./cards

# 2. Un candidato aprobado por una persona, verificado en el sandbox
python -m autopilot sandbox "examples/insurance_claims_v0.1.yaml" \
    ./cards/CARD-*.json examples/insurance_claims_sandbox_run_0*.yaml \
    --candidate CAND-... --approved-by claims_ai_owner \
    --approved-at 2026-07-17T12:30:00Z --output report.json

# 3. La revisión independiente, firmada con Ed25519
python -m autopilot review-keygen keys/private.pem keys/public.pem
python -m autopilot review report.json --decision approve_staged_release \
    --reviewer release_owner --role release_reviewer --rationale "..." \
    --reference REL-001 --decided-at 2026-07-17T16:00:00Z \
    --private-key keys/private.pem --output review.json

# 4. Al ledger append-only, y al bundle que verifica esta página
python -m autopilot audit-record ledger.sqlite3 ./cards/CARD-*.json
python -m autopilot audit-record ledger.sqlite3 report.json
python -m autopilot audit-record ledger.sqlite3 review.json --public-key keys/public.pem
python -m autopilot audit-verify ledger.sqlite3
python -m autopilot audit-export ledger.sqlite3 --output bundle.json

    El ledger de demostración de esta página se genera con python scripts/build_demo_ledger_bundle.py, que ejecuta exactamente ese recorrido sobre los ejemplos del repositorio y escribe los dos assets del sitio. El repositorio vuelve a verificar el bundle en cada pasada del gate con el mismo verificador que acabas de ejecutar, pero bajo Node.

    Alcance

    Qué demuestra esto, y qué no.

    Lo decimos antes de que lo preguntes: una verificación que no declara sus límites no sirve para decidir nada.

    Demuestra integridad, no autoría. La cadena prueba que los bytes no han cambiado desde que se escribieron. Quien controla el fichero puede reescribir la cadena entera y recalcularla: por eso la autoridad no es la cadena, son las firmas Ed25519 que viajan dentro del ledger y verifica el CLI.

    Solo SHA-256, a propósito. Esta página no pide claves, no ejecuta el producto y no habla con ningún servidor. Por eso tampoco verifica firmas: el navegador no expone Ed25519 de forma fiable. El CLI sí, y lo puedes ver en el stand con la clave pública del bundle.

    El bundle es una copia. Lo que verificas es el bundle que te han dado, no el ledger original. El bundle declara el SHA-256 del fichero del que salió: la correspondencia con ese fichero concreto la comprueba quien tenga acceso a él.

    No es una certificación. Ni acredita conformidad con el AI Act ni sustituye una auditoría. Aporta evidencia técnica fechada sobre la que otra persona puede decidir, y nada habilita producción por sí solo.
