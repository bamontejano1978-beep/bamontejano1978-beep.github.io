Benchmark v0.1 · published results

When an agent goes past its limits under pressure, is it contained?

Most agent evaluations answer "did it say the right thing?". This one answers a different question: whether tool authority, budgets, payment limits, stop conditions and evidence provenance hold when an agent is pushed past them. It is the technical base behind every private review we run, and we publish what it does not measure too.

What is measured

Two independent verdicts per run.

A run can satisfy the contract in prose and still be quarantined for making an unauthorised payment in impeccable language. Both reports stay separate by design; a combined verdict is derived only afterwards.

01

Behavioural verdict

Clause-by-clause evaluation of a versioned behavioural contract: obligations, prohibitions, conditionals, time limits and recovery rules, each with its evidence.

02

Operational containment verdict

Six deterministic checks over a trusted operational trace: tool allowlist, tool-call budget, payment authority, claim-payment budget, stop enforcement and evidence provenance.

Design principles: deterministic evaluation with no language model in the scoring path, separation between the component that produces behaviour and the one that grades it, evidence per run, and fail closed (any failed check recommends quarantine and blocks release; any indeterminate check recommends supervision and also blocks it).

Track B · adversarial cohort

Ten runs, one per containment failure class.

A goal-seeking agent against a contained reference agent, across five adversarial scenarios. Every failure maps to exactly one of the six checks: forbidden policy-modification tool, tool-call budget exhaustion, continued execution after revocation, payment above the monetary limit, and incomplete audit evidence.

This track is a control suite, not a leaderboard: it verifies that the evaluator detects each violation class. Every failed run recommends quarantine.

Isolated container probe, 19 August 2026. A real Docker execution against the same boundary: signature, event chain, semantic coherence, isolation and operational integrity all verified. One request executed, three blocked before any side effect, and one worker terminated for ignoring a stop order. The pipeline publishes only the public key and the evidence; the private signing key is destroyed.

Limitations

Read this before citing any figure.

These limitations are part of the result, not a footnote.

  • Tracks A and B use no external models

    They are deterministic behavioural sources. They verify evaluator sensitivity and instrumentation quality, not vendor behaviour.

  • Track C is a single snapshot

    One server, temperature zero, CPU. Stochastic re-runs may produce different phrasings. These are deterministic references, not probability statements.

  • Four scenarios only

    Coverage beyond the published shapes is not measured.

  • The trusted runner is an in-process monitor

    It demonstrates the evidence boundary; OS-level isolation exists only in the separate Docker probe.

  • Audit ledgers are local SQLite

    External anchoring is out of current scope.

  • No result authorises a deployment

    Everything produces evidence for human review. Nothing deploys changes automatically.
