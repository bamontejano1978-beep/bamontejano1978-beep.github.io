Verification on your device

Bring a ledger. Check it yourself, with nothing installed and no trust in us.

An audit ledger is worth nothing if only its author can verify it. We export ours into a bundle and your browser recomputes the whole SHA-256 chain: every payload, every hash, every link to the one before. If somebody edited a byte after it was written, you see it here, on your screen.

    Before this page

    Where the bundle comes from, in four steps.

    The bundle is not manufactured for the demo: it is the output of the same route we run with a client. One contract, one candidate approved by a human, one independently signed review, and a ledger that records all of it. 

    # 1. From the contract to the change card: hypotheses, no changes applied
python -m autopilot diagnose "examples/insurance_claims_v0.1.yaml" \
    "examples/insurance_claims_trajectory_fail_v0.1.yaml" --output-dir ./cards

# 2. A candidate approved by a human, verified in the sandbox
python -m autopilot sandbox "examples/insurance_claims_v0.1.yaml" \
    ./cards/CARD-*.json examples/insurance_claims_sandbox_run_0*.yaml \
    --candidate CAND-... --approved-by claims_ai_owner \
    --approved-at 2026-07-17T12:30:00Z --output report.json

# 3. The independent review, signed with Ed25519
python -m autopilot review-keygen keys/private.pem keys/public.pem
python -m autopilot review report.json --decision approve_staged_release \
    --reviewer release_owner --role release_reviewer --rationale "..." \
    --reference REL-001 --decided-at 2026-07-17T16:00:00Z \
    --private-key keys/private.pem --output review.json

# 4. Into the append-only ledger, and into the bundle this page verifies
python -m autopilot audit-record ledger.sqlite3 ./cards/CARD-*.json
python -m autopilot audit-record ledger.sqlite3 report.json
python -m autopilot audit-record ledger.sqlite3 review.json --public-key keys/public.pem
python -m autopilot audit-verify ledger.sqlite3
python -m autopilot audit-export ledger.sqlite3 --output bundle.json

    The demo ledger on this page is built by python scripts/build_demo_ledger_bundle.py, which runs exactly that route over the repository examples and writes both site assets. The repository re-verifies the bundle on every gate run with the same verifier you just used, under Node.

    Scope

    What this proves, and what it does not.

    We say it before you ask: a verification that hides its limits cannot support a decision.

    It proves integrity, not authorship. The chain proves the bytes have not changed since they were written. Whoever controls the file can rewrite the whole chain and recompute it: that is why the authority is not the chain but the Ed25519 signatures carried inside the ledger, which the CLI verifies.

    SHA-256 only, on purpose. This page asks for no keys, does not run the product and talks to no server. That is also why it cannot verify signatures: browsers do not expose Ed25519 reliably. The CLI does, and you can watch it at the stand with the public key inside the bundle.

    The bundle is a copy. What you verify is the bundle you were handed, not the operator's original ledger. The bundle declares the SHA-256 of the file it came from: matching that file is something only somebody with access to it can confirm.

    It is not a certification. It neither certifies AI Act conformity nor replaces an audit. It provides dated technical evidence a person can decide on, and nothing here authorises deployment by itself.
